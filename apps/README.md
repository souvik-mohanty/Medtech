# MedTech Flutter Apps

Six independent Flutter projects, one per non-admin role. Each is a
self-contained app (no shared package between them) with the same internal
structure — see any app's own README for setup/run instructions and its
`lib/` layout.

| App | Role | Login | Sample feature |
|---|---|---|---|
| `patient_app` | Patient | Google OAuth only | Real: browse a franchise's catalog, place an online order |
| `franchise_app` | Franchise Owner | Google OAuth only | Real: 4-tab dashboard — billing (with print), inventory, branding, payment gateway config |
| `doctor_app` | Doctor | Google OAuth + franchise/clinic ID | Mock: static "Today's Appointments" list |
| `lab_technician_app` | Lab Technician | Google OAuth + franchise ID | Mock: static "Assigned Lab Tests" list |
| `delivery_partner_app` | Delivery Partner | Google OAuth + franchise ID | Mock: static "Delivery Queue" list |
| `customer_support_app` | Customer Support | Google OAuth only, platform-wide | Mock: static "Support Tickets" list |

Patient and Franchise Owner call real, working backend endpoints. The other
four roles have no backend module built yet, so their "sample feature" is
static mock data in `lib/features/home/home_screen.dart` illustrating the
intended UI — clearly commented as such, not wired to any API.

Admin has no Flutter app — see `../admin-web` (React) instead.

## Important: Flutter SDK was not available when these were scaffolded

Each app has `pubspec.yaml` and `lib/` hand-written, but **no platform
folders** (`android/`, `ios/`, etc.) — those are generated by the Flutter
CLI, which wasn't installed in the environment that created this scaffold.
Once Flutter is installed, run inside each app folder:

```bash
flutter create . --platforms=android,ios --org com.company.medtech
flutter pub get
```

This is safe to run against an existing `pubspec.yaml`/`lib/` — it only adds
the missing platform folders, it does not overwrite existing code.

## What's scaffolded vs. not

Every app has: Google Sign-In wired to the backend's
`POST /api/auth/oauth/google`, the JWT attached to every subsequent request
via a Dio interceptor (`lib/core/api_client.dart`), JWT persistence, and a
role-aware login screen (franchise ID field shown only where required). See
the table above for what's real vs. mock past that. See
`docs/PROJECT_SPEC.md` for what each role's app needs to eventually cover.

## Theming

Each app has a `lib/theme/app_theme.dart` placeholder (Material 3, a seed
color) — the single point to swap in the shared design system once it's
provided, without touching individual screens.
